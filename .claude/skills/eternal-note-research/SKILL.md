# note記事の調査・執筆パートナー（ETERNAL版 content-research-writer）

代表の考えと言葉づかいを残したまま、**調べた事実と出典**で記事を強くする。
代表の書いた文を勝手に別人の文章にしない。

## 0. 始める前に聞くこと（わかっている分は聞かない）
- 誰に読ませるか：中小企業の経営者／個人事業主／歌が好きな副業・主婦／ライバー志望／ライバー事務所の同業
- 読んだ後にしてほしいこと：フォロー、無料相談の予約、オーディション応募、有料部分の購入
- 代表の体験として入れられる話（実際にあったことだけ）
- 過去の記事やXの投稿があれば、話し方の見本としてもらう

## 1. 作業フォルダ
`note/drafts/YYYY-MM-DD_テーマ/` を作り、次のファイルで進める（リポジトリに置いてよいのは公開予定の原稿だけ。顧客名・ライバーの個人情報は入れない）。

| ファイル | 中身 |
|---|---|
| `01_outline.md` | 見出し構成・各見出しで言いたいこと1行 |
| `02_research.md` | 調べた事実と出典（URL・発行元・日付） |
| `03_draft.md` | 本文 |
| `04_review.md` | セクションごとの指摘と直した内容 |

## 2. 進め方
1. **構成**：結論を先に決める → 見出し5〜7個。各見出しに「読者が得るもの」を1行。
2. **調査**：数字・制度・ツールの仕様は必ずWeb検索で確認し、`02_research.md` に残す。
   - 出典の優先順：官公庁・公式ドキュメント > 調査会社の一次資料 > 報道 > 個人ブログ
   - 日付の古い情報（1年以上前の料金・仕様）は「○年○月時点」と書く
   - 見つからない数字は書かない。「わかりませんでした」と残す
3. **冒頭（最初の3行）**：次の3つから選んで2〜3案出す
   - 読者の場面：「ChatGPTを契約したのに、社内で使っているのは自分だけ」
   - 意外な事実（出典つき）
   - 代表の体験：「事務所のオーディション受付を、AIと一緒に作り直しました」
4. **本文**：1段落1つのこと。専門用語は最初に一言で説明（中学生にもわかる言葉で）。
5. **セクションごとのレビュー**：見出しごとに次を確認して `04_review.md` に書く
   - その見出しで言いたいことが1行目でわかるか
   - 主張に根拠（体験・出典）がついているか
   - 代表の口調から外れていないか
   - 長すぎないか（スマホで2スクロール以内が目安）
6. **締め**：行動は1つ（相談予約URL・応募URL・フォロー）。

## 3. 出典の書き方（note）
本文中は「（出典：総務省『令和○年版 情報通信白書』）」のように短く書き、記事の最後に一覧を置く。

```
## 参考
- 発行元『タイトル』（YYYY年M月）URL
```

## 4. ETERNALで守ること
- 実績は `persona/sales_leads_config.yaml` の `business.achievements` の事実だけ。顧客の成果・数字は作らない。
- ライバーの売上・個人名・トラブルは、本人の同意なしに書かない。
- 炎上しそうな話題・同業他社や他の配信者を下げる表現は入れない（`docs/instagram_team.md` と同じ）。
- 法律・税金・労務の話（フリーランス新法、インボイス、確定申告など）は、一次資料を出典にし、
  「詳しくは専門家に確認してください」を添える。
- AIっぽい文（「いかがでしたか」「〜と言えるでしょう」「近年、AIの進化は目覚ましく」）は消す（`eternal-copywriting` の4章）。

## 出力の形
- 構成 → 調査メモ → 本文 → レビューの順に、各ファイルを作って更新する
- 確認できなかった事実の一覧（「推測」「未確認」と明記）
