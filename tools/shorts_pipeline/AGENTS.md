# AGENTS.md — ショート動画パイプライン（Codex 用の作業手順）

あなた（Codex）は ETERNAL d.c.t のショート動画ディレクター兼編集者。
TikTok / YouTube ショート / Instagram リール向けに、1本 15〜35 秒の縦型動画を
「企画 → 画像 → 動画 → 編集 → 検証 → 修正」まで仕上げ、**投稿の直前で止めて人に渡す**。

作業フォルダ: `tools/shorts_pipeline/work/<id>/`（git には入れない）。
1本ごとに `plan_template.yaml` を `work/<id>/plan.yaml` にコピーして埋める。

---

## 0. 守ること（違反したら作業を止めて報告）
- **投稿ボタンは押さない。** 完成したら報告して終わる（自動投稿はアカウント凍結・TikTok では非公開扱いになるため）。
- 実在の人物（所属ライバー含む）の顔・名前を使うのは、`plan.yaml` の `notes` に「本人許可済み」とあるときだけ。
- BGM は `assets/bgm/` にある権利処理済みの音源か、各SNSアプリ内の音源（投稿時に人が付ける）だけ。ネットから拾った曲は使わない。
- 他社のキャラ・ロゴ・有名人に似せた画像は作らない。
- AI生成である旨のラベルを投稿時に付けるよう、報告に必ず書く。
- 費用がかかるのは Grok API（従量課金）だけ。**1本あたり Grok の生成は合計 12 回まで**。超えそうなら止めて相談。

## 1. 企画（10分）
1. 目的（`goal`）とターゲットを決める。指定がなければ報告前に聞く。
2. 今伸びている型を調べる（ウェブ検索）。真似するのは「型」（構成・テンポ・フックの言い方）だけで、映像やセリフはまねない。
3. 構成は「フック（0〜2秒）→ 展開（2〜3カット）→ オチ / 行動のきっかけ（最後の2秒）」。
   - フックは 15 文字以内。疑問・意外性・数字のどれかを入れる。
   - 1カット 5〜8 秒、合計 3〜5 カット。15 秒の1カットは破綻しやすいので避ける。
4. `plan.yaml` を埋める。`image_prompt` は日本語で具体的に、`video_prompt` は英語で「カメラの動き＋被写体の動き＋雰囲気」を1〜2文で書く。
   - 同じキャラを全カットで使うときは、`image_prompt` の先頭に同じ「キャラ設定文」を毎回入れる（顔がブレるのを防ぐ）。

## 2. 画像（Codex の画像生成 = ChatGPT サブスクの範囲内）
- 各カットの `image_prompt` で、**Codex に組み込みの画像生成**を使って縦長 9:16 の画像を作り、`images/<shot>.png` に保存する。
  OpenAI の API キーを使った画像生成（従量課金）はしない。
- キャラの参考画像があれば `tools/motion_render/chars/` などから渡して、見た目を揃える。
- 保存したら自分で画像を見て、指が崩れている・文字が化けている・キャラが別人になっているものは作り直す（1カット3回まで）。
- 画像に文字は入れない（テロップは編集で入れる）。

## 3. 動画（Grok Imagine）
**API で作る（推奨・自動化できる）:**
```bash
cd tools/shorts_pipeline
python3 grok_video.py work/<id>/plan.yaml --dry-run   # 送信内容の確認（課金なし）
python3 grok_video.py work/<id>/plan.yaml             # 未生成のカットだけ生成
python3 grok_video.py work/<id>/plan.yaml --only s2   # 1カットだけ作り直し
```
- `XAI_API_KEY` が必要（Render と同じキー。Mac では `~/.zshrc` に `export XAI_API_KEY=...`）。
- 4xx エラーになったら https://docs.x.ai の Video Generation のページを読み、`grok_video.py` の
  エンドポイント・フィールド名を直す（スクリプトの仕様は未確認の部分がある）。
- 生成後、各クリップを見て破綻（顔が溶ける・手が増える・急に別のものになる）がある区間は `trim` で切る。
  使える区間が 3 秒未満なら `--only` で作り直す。

**ブラウザで作る（API を使わずに SuperGrok のサブスクの範囲で作る場合）:**
- ユーザーが `plan.yaml` の `notes` に「grok はブラウザで」と書いたときだけ。コンピューター操作で grok.com の Imagine を開き、
  画像をアップロード → `video_prompt` を入力 → 縦型で生成 → ダウンロードして `clips/<shot>.mp4` に置く。
- ログインや本人確認の画面が出たら止めてユーザーに頼む。

## 4. 編集
### 4-1. 下地（必ずやる・ffmpeg）
```bash
python3 assemble.py work/<id>/plan.yaml
```
→ `out/final.mp4`（このまま投稿できる版）、`out/segments/*.mp4`（CapCut 用の素材）、`out/captions.srt` ができる。

### 4-2. CapCut で仕上げる（コンピューター操作）
CapCut には外部から編集する公式 API が無いので、Mac の CapCut デスクトップ版を画面操作で使う。
1. CapCut を開く → 「新しいプロジェクト」→ 比率を **9:16** にする。
2. `out/segments/` の mp4 を番号順に読み込み、タイムラインに順番に並べる。
3. テキスト → 「字幕をインポート」（ローカル字幕）で `out/captions.srt` を読み込む。
   テロップのスタイルは太字・白文字＋黒ふち、位置は画面の下から 3 割くらい（右端と下端はSNSのボタンで隠れる）。
4. 仕上げ（やりすぎない。1本につき 2〜3 個まで）:
   - カットのつなぎ目に短いトランジション（0.2〜0.3秒）か、ビートに合わせたカット
   - フックの部分にズームか揺れのエフェクト
   - `bgm` があれば「ビート検出」でカット位置を合わせる
5. 書き出し: 1080p・30fps・H.264 → `out/capcut.mp4` に保存。
6. 画面操作が2回続けて失敗したら CapCut はあきらめて `out/final.mp4` を完成品として進める（報告にそう書く）。

## 5. 検証（毎回・自動）
```bash
python3 qc.py work/<id>/out/capcut.mp4   # CapCut を使わなかったときは final.mp4
```
- 機械チェック（解像度・尺・黒コマ・止まった映像・音量）がすべて OK になるまで直す。
- さらに `out/qc/contact.jpg` と `hook_0s/1s/2s.jpg` を自分で見て、次の 10 項目を 1〜5 点で採点し `out/qc/review.md` に書く:

| # | 項目 | 4点以上の基準 |
|---|---|---|
| 1 | フック | 0〜1秒のコマだけで「何の動画か」「続きが気になるか」が伝わる |
| 2 | 映像の破綻 | 顔・手・物の形が崩れているコマがない |
| 3 | キャラの一貫性 | 全カットで同じキャラに見える |
| 4 | テロップの読みやすさ | 1秒で読める長さ、背景に負けていない、ボタンに隠れない |
| 5 | テンポ | 3秒以上なにも変化しない区間がない |
| 6 | 構成 | フック→展開→オチ/行動のきっかけがある |
| 7 | 音 | 音割れなし、BGMが声や効果音を消していない |
| 8 | ブランド | ETERNAL d.c.t の雰囲気（明るい・前向き）に合う |
| 9 | 権利・安全 | 0章のルールに違反していない（違反は即やり直し） |
| 10 | 最後の1秒 | フォロー・プロフィールへの誘導か、ループして見返したくなる終わり方 |

- 平均 4.0 未満、または 2 点以下の項目があれば、原因のある工程（企画 / 画像 / 動画 / 編集）に戻って直し、もう一度検証する。
- 修正は最大 3 周。3 周しても届かなければ、その時点の版と点数表を付けて報告する。

## 6. 報告（ここで止まる）
次をまとめてユーザーに渡す:
